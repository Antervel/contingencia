# E1-01: Repository skeleton and prototype Compose stack

**Epic:** E1 (mta + imap prototype)
**Size:** S
**Depends on:** none
**Hypotheses covered:** none directly (this ticket is the foundation for all of them)

## Context

Every other ticket needs a place to put files and a way to start the containers. This ticket creates the empty structure and a Compose file that starts placeholder containers on a private network, so the later tickets only fill in contents. Decisions made here (user IDs, volume paths, network names) are hard to change later, so they are written down explicitly.

## What to do

1. Create the folder layout from section 4 of `EPIC.md`: `mta/`, `imap/`, `prototype/config/postfix/`, `prototype/config/dovecot/`, `prototype/tests/`, `reference/`, `docs/`.
2. Create `compose.yaml` with three services: `mta`, `imap`, and `main` (a placeholder for the sink, filled in by E1-02).
3. Define **one private network** for the stack. All three services join it. Containers reach each other by service name (`imap`, `mta`, `main`).
4. Define the volumes and their mounts:
   - `prototype/config` mounted **read-only** at `/config` into `mta` and `imap` (the stand-in for the config volume that `admin` will write later).
   - A named volume `mail` mounted read-write at `/var/mail/vhosts` into `imap` only.
   - A named volume `queue` mounted read-write at `/var/spool/postfix` into `mta` only.
5. Publish ports **for testing only**, bound to `127.0.0.1` on the host:
   - `mta` port 25 as host port `2525`
   - `mta` port 587 as host port `5587`
   - `imap` port 143 as host port `1143`
   - `main` SMTP port as host port `2526`, and its web or API port as `8025` if the sink has one
   These published ports exist only in the prototype. The final system will not publish IMAP or submission.
6. Decide and document the **user and group IDs** used by the services:
   - A `vmail` user (for example uid 5000) owning mail storage in `imap`.
   - A shared group (for example gid 5001, named `contingency-config`) that can read the config files in both containers.
   Write the chosen numbers in `docs/FINDINGS.md` under a heading "Identity plan".
7. Add a `.gitignore` for editor files and test output.
8. Add a short `README.md` at the top level: what this prototype is, how to start it (`docker compose up --build`), how to stop it, and where the test fixtures are defined (link to `EPIC.md` section 3).
9. Pick the Debian release for the images and write it down in `docs/FINDINGS.md` under "Versions". Use the current stable release, and pin it by tag in the Dockerfiles (E1-03 and E1-04).

## Acceptance criteria

- `docker compose config` validates with no errors.
- `docker compose up` starts all three services without crashing. Placeholder commands that stay running (such as sleeping) are acceptable at this stage.
- Services can reach each other by name. From `mta`: `getent hosts imap` and `getent hosts main` return addresses.
- The config folder is visible read-only in `mta` and `imap` at `/config`. Attempting to write a file there from inside a container fails.
- The `mail` and `queue` volumes survive `docker compose down` and come back with `docker compose up` (verify by writing a marker file).
- The identity plan and Debian release are recorded in `docs/FINDINGS.md`.

## How to test

```
docker compose config
docker compose up -d
docker compose exec mta getent hosts imap
docker compose exec mta getent hosts main
docker compose exec imap sh -c 'touch /config/x' ; echo "exit code: $?"      # must fail (read-only)
docker compose exec imap sh -c 'touch /var/mail/vhosts/marker'
docker compose down
docker compose up -d
docker compose exec imap ls /var/mail/vhosts/marker                          # must still exist
```

## Notes and pitfalls

- Use the service name `main` for the fake server on purpose: the real appliance will have `main` as a *setting*, and tests should look the same.
- Do not publish any port on `0.0.0.0`. Bind explicitly to `127.0.0.1`.
- Do not use bind-mount paths that depend on the developer's machine. Use paths relative to the repository.

`compose.yaml`, folder skeleton, `README.md`, `docs/FINDINGS.md` (first two sections).
