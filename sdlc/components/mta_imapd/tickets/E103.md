# E1-03: `imap` container: Dovecot with two-name mailboxes

**Epic:** E1 (mta + imap prototype)
**Size:** M
**Depends on:** E1-01

## Context

The copy delivered by the appliance (Postfix, E1-04) is addressed to the internal
delivery name (`alice^client.test@copies.invalid`), while the user logs in to read it as
`alice@client.test`. The `imap` container must therefore answer to both names and give both
names the same mailbox.

Per EPIC section 3.2, one passwd-file serves as both user database and password database:
one line per name, two lines per mailbox, sharing one home directory.

## What to do

1. Create `imap/Dockerfile`: Debian base image pinned to the release decided in `docs/FINDINGS.md`
   (Debian 13 "Trixie"), installing Dovecot (`dovecot`, `dovecot-imapd`, `dovecot-lmtpd`).
2. Write the hand-written Dovecot configuration in `prototype/config/dovecot/`:
   - `dovecot.conf`: protocols (`imap`, `lmtp`), listeners (IMAP on 143, LMTP for Postfix),
     auth via the passwd-file, plain auth for the internal network.
   - `passwd`: two lines per mailbox — the login name with a SHA-512 crypt password, and the
     internal delivery name with no password (login disabled) — sharing one home directory.
3. Update `compose.yaml`: the `imap` service builds from `imap/Dockerfile`, keeps the config
   volume read-only at `/config` and the `mail` volume read-write at `/var/mail/vhosts`.
4. Keep the mail storage under `/var/mail/vhosts/<domain>/<user>` owned by the `vmail` user
   (uid 5000) from the identity plan.

## Acceptance criteria

- `docker compose up -d imap` starts Dovecot without crashing.
- The IMAP listener (143) and the LMTP listener (for Postfix) are up; the SASL auth listener
  for Postfix over the private network is configured (verify listener settings).
- `doveadm user alice@client.test` and `doveadm user alice^client.test@copies.invalid` resolve
  to the same home directory (one mailbox).
- Login with the login name and password works; the delivery name cannot log in.

## How to test

```
docker compose up -d imap
docker compose exec imap doveadm user alice@client.test
docker compose exec imap doveadm user alice^client.test@copies.invalid
docker compose exec imap doveadm auth test alice@client.test alice-pass
docker compose exec imap doveadm auth test alice^client.test@copies.invalid <password>
```

## Notes and pitfalls

- Dovecot runs its master as root and drops privileges per user; the `vmail` user (uid 5000)
  must own the mail volume.
- The `^` separator must be accepted by Dovecot as part of the user name (H3).

## Outputs

`imap/Dockerfile`, `prototype/config/dovecot/`, updated `compose.yaml`, notes in `docs/FINDINGS.md`.
