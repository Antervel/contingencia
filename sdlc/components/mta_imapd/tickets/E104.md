# E1-04: `mta` container: baseline Postfix relay to `main`

**Epic:** E1 (mta + imap prototype)
**Size:** M
**Depends on:** E1-01, E1-02, E1-03
**Hypotheses covered:** H2 (partly), H5 (partly)

## Context

Before adding the copy trick, `mta` must behave as an ordinary **backup mail server**: it accepts mail for the client domains and relays it to `main`, holding it in the queue while `main` is unavailable. This ticket builds that baseline, plus the plumbing for the internal mailbox domain `L` (delivery to `imap` over LMTP), but **does not yet create copies**. Keeping the copy rule for the next ticket means that if something breaks, we know which half caused it.

All tables are written with Postfix's `texthash:` type, so no `postmap` step is needed (H5). If `texthash` turns out not to work for a table, that is recorded here, and the fallback is `hash:`.

## What to do

1. Write `mta/Dockerfile`:
   - Debian release from E1-01.
   - Install Postfix from Debian packages, plus small diagnostic tools.
   - Run Postfix in the **foreground** as the container's main process.
   - Logging to standard output.
2. Write the Postfix configuration. Keep static settings (in `main.cf` and `master.cf`) in the image or a static file, and the generated tables in `prototype/config/postfix/`, mounted at `/config/postfix/`. Required settings:
   - **Identity:** a host name for the appliance, for example `backup.client.test`.
   - **No local mail delivery:** the server must not treat any domain as a local machine domain beyond its own host name.
   - **Relay domains:** `client.test` and `other.test`, read from a table file `/config/postfix/relay_domains`.
   - **Transport table:** route each relay domain to `[main]:25` (square brackets: no MX lookup, so mail cannot loop back to the appliance). Table file `/config/postfix/transport`. In the prototype only, also route `outside.test` to `[main]:25`.
   - **Internal mailbox domain `L`:** declare `copies.invalid` as a virtual mailbox domain, delivered by `virtual_transport = lmtp:inet:imap:24`, with a table file `/config/postfix/virtual_mailboxes` listing every internal delivery address (one per fixture mailbox). **Do not** add it to the relay domains.
   - **Queue lifetime:** `maximal_queue_lifetime` and `bounce_queue_lifetime` both set to `100d`.
   - **No spam checks, no virus checks**, no DKIM, no TLS in the prototype.
   - **Relay restrictions:** unauthenticated clients may send only to relay domains. Nobody may use the server to relay to arbitrary destinations except through authenticated submission (set up in E1-08).
3. Create the table files with fixtures from `EPIC.md` section 3. Every file has a comment header explaining its purpose, since these become the reference formats.
4. Add a health check: Postfix answers on port 25.
5. Add `mta` to `compose.yaml` with the volumes from E1-01. Ensure it starts after `imap`.
6. Confirm that Postfix is **reading** the table files you wrote: look up a known key with `postmap -q KEY texthash:/config/postfix/relay_domains` inside the container, and with `postconf` check each parameter value.

## Acceptance criteria

- `docker compose up -d` starts `mta` and it stays healthy.
- `postfix check` reports no problems.
- `postconf -n` shows the intended values, including the 100-day queue lifetimes.
- **Relay works with `main` up:** a message to `alice@client.test` sent to `mta` (host port 2525) arrives at the sink unchanged within a minute. Because the copy rule does not exist yet, the mailbox in `imap` receives nothing.
- **Relay queues with `main` down:** with `main` stopped, the message is accepted by `mta` (the sender sees success) and sits in the queue. `postqueue -p` lists it, with a deferral reason saying `main` is unreachable.
- **Open relay protection:** a message from an unauthenticated client to `someone@elsewhere.test` is rejected.
- **Internal domain accepted (H2, first half):** `postmap -q 'alice^client.test@copies.invalid' texthash:/config/postfix/virtual_mailboxes` returns a result, and Postfix accepts a message addressed to that recipient when injected locally with `sendmail` inside the container (it must be delivered to `imap` and show in alice's INBOX).
- Every `texthash:` table used is confirmed readable with `postmap -q` and appears in `postconf` output (H5, first half).

## How to test

```
docker compose up -d --build mta
docker compose exec mta postfix check
docker compose exec mta postconf -n | grep -E 'relay_domains|transport_maps|virtual_|queue_lifetime'

# Main up
swaks --server 127.0.0.1:2525 --from s@sender.test --to alice@client.test --body "relay test"
prototype/tests/lib/sink.sh count                   # expect 1

# Main down
docker compose stop main
swaks --server 127.0.0.1:2525 --from s@sender.test --to alice@client.test --body "queue test"
docker compose exec mta postqueue -p                # expect 1 queued message
docker compose start main

# Open relay check
swaks --server 127.0.0.1:2525 --from s@sender.test --to someone@elsewhere.test ; echo "exit: $?"   # expect rejection

# Internal domain via local injection
docker compose exec mta sh -c "printf 'Subject: internal\n\nhello\n' | sendmail -f s@sender.test 'alice^client.test@copies.invalid'"
curl --url 'imap://127.0.0.1:1143/INBOX' --user 'alice@client.test:alice-pass'
```

## Notes and pitfalls

- If Postfix says "relay access denied" for a message that should be accepted, check that the domain is in the relay domains table **and** that the exact table type is accepted for that parameter. Record the exact error text if `texthash:` is not accepted there (H5).
- If a message to `alice@client.test` is delivered to the `imap` container instead of the sink, a domain is mistakenly local. Check `mydestination`.
- A deferral reason mentioning "Connection refused" or "timed out" when `main` is stopped is correct. Any other reason means something else is wrong.
- Do not use `.invalid` as a relay domain. It is only the internal mailbox domain.
