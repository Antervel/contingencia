# E1-05: The copy rule: relay the original, deliver the copy

**Epic:** E1 (mta + imap prototype)
**Size:** L
**Depends on:** E1-03, E1-04
**Hypotheses covered:** H1, H2, H3, H7 (end to end)

## Context

This is the central ticket of the epic. The whole product exists because of one behavior: when mail for `alice@client.test` arrives, Postfix must

1. **queue the original** for delivery to `main`, and
2. **also deliver a copy** to `alice^client.test@copies.invalid`, which Dovecot stores in the mailbox that `alice@client.test` logs into.

The mechanism is a Postfix **recipient BCC map**. The assumption (H1) is that a recipient BCC rule also applies to mail that Postfix is only relaying, not delivering locally. We believe it does, because BCC is applied while the message is being accepted, before routing. We have not seen it work. If H1 is false, the fallback in `EPIC.md` section 6 changes the whole plumbing, so this ticket must be done carefully and with evidence.

This ticket also confirms, end to end, H2 (the `.invalid` domain), H3 (the `^` character) and H7 (two names, one mailbox).

## What to do

1. Create the table file `prototype/config/postfix/recipient_bcc`, as a `texthash:` table, with one line per fixture mailbox:
   - `alice@client.test` maps to `alice^client.test@copies.invalid`
   - `bob@client.test` maps to `bob^client.test@copies.invalid`
   - `carol@other.test` maps to `carol^other.test@copies.invalid`
   Do **not** add the catch-all yet (E1-06).
2. Set `recipient_bcc_maps` in Postfix to read this table. Reload Postfix.
3. Send a message to `alice@client.test` with `main` **up** and observe:
   - the sink receives the original,
   - `imap` stores a copy in alice's INBOX.
4. Send a message with `main` **down** and observe:
   - the original is held in the queue,
   - the copy is **still** delivered to alice's INBOX immediately (this is the whole point of the product).
5. Capture the **evidence** for each observation, not just the result:
   - Postfix log lines showing the BCC copy being created and delivered over LMTP.
   - `postqueue -p` output showing exactly one queued item (the original) and no stuck copy.
   - The IMAP listing and the full text of the message in alice's INBOX.
   - The raw message in the sink, compared against the copy.
6. Compare the **content** of the original and the copy:
   - Both must have the same body and the same visible headers.
   - Record any difference in envelope or headers. Typical expected difference: the copy has a different `Delivered-To` or `Received` line, and its envelope recipient is the internal address. Record all differences. If any difference would matter to a human reader (for example, a changed `To` header), that is a finding.
7. Check what the **user sees**: when alice logs in over IMAP, the message must look like an ordinary message addressed to her, and the visible `To` header must still say `alice@client.test`. Nothing in the visible headers should reveal the `^` address.
8. Repeat for bob and carol to check that the domain part of the internal name is handled correctly.
9. Try a message to **two recipients** at once (`alice@client.test` and `bob@client.test`): each mailbox must receive exactly one copy and the sink receives the original exactly once per recipient (or once with both recipients; record which).
10. Try the **negative cases**:
    - A message to an address with no BCC entry (`nobody@client.test`) is relayed to `main` and no copy appears anywhere (the catch-all does not exist yet).
    - A message sent directly from outside to `alice^client.test@copies.invalid` is **not accepted** from the network. Postfix must not allow anyone on the internet to inject mail straight into the internal domain. Confirm the behavior, and if it is accepted, note it as a finding for E1-06 (recipient policy) and for hardening.

## Acceptance criteria

- **H1 PASS:** with `main` down, a message to `alice@client.test` yields exactly one queued original **and** exactly one copy in alice's INBOX. With `main` up, it yields one original in the sink and one copy in alice's INBOX.
- **H2 PASS:** the `.invalid` internal domain is accepted at every step: as a BCC target, as a virtual mailbox domain, and in LMTP delivery.
- **H3 PASS:** the `^` character is accepted at every step, with no errors or rewriting in the logs.
- **H7 PASS:** alice logs in as `alice@client.test` and reads the copy.
- The user-visible `To` header of the copy equals the original's `To` header.
- The queue holds **no** item addressed to `copies.invalid`. The copy is delivered immediately and never queued toward `main`.
- The evidence listed in step 5 is saved in `docs/evidence/E1-05/` (log excerpts, command outputs, raw messages).
- If any of H1 to H3 fails, the failure is documented with the exact error text and the corresponding fallback from `EPIC.md` section 6 is **proposed** (not yet applied) in `docs/FINDINGS.md`, and the epic owner is notified before further tickets proceed.

## How to test

```
# Reset state between runs
prototype/tests/lib/sink.sh clear
docker compose exec imap sh -c 'rm -rf /var/mail/vhosts/client.test/alice/Maildir/new/* /var/mail/vhosts/client.test/alice/Maildir/cur/*'
docker compose exec mta postsuper -d ALL

# Main down scenario
docker compose stop main
swaks --server 127.0.0.1:2525 --from sender@sender.test --to alice@client.test \
      --header 'Subject: copy rule test' --body 'hello alice'
docker compose exec mta postqueue -p                    # one item, to alice@client.test
docker compose logs mta | tail -50                      # BCC, LMTP delivery lines
curl --url 'imap://127.0.0.1:1143/INBOX' --user 'alice@client.test:alice-pass'   # lists 1
curl --url 'imap://127.0.0.1:1143/INBOX;MAILINDEX=1' --user 'alice@client.test:alice-pass'  # message text

# Main up, flush, compare
docker compose start main
docker compose exec mta postqueue -f
prototype/tests/lib/sink.sh raw 1                       # compare with the IMAP copy

# Negative case: direct injection into the internal domain
swaks --server 127.0.0.1:2525 --from x@sender.test --to 'alice^client.test@copies.invalid' ; echo "exit: $?"
```

## Notes and pitfalls

- **How BCC addresses are matched:** Postfix looks up the full recipient address first. Make sure the recipient is looked up in the form it arrives in (including case). Use lowercase everywhere in the fixtures and note whether mixed-case senders behave differently.
- **Where the copy appears in the logs:** look for a second queue ID created for the copy. Understand what each line means before concluding anything.
- If the copy is made but delivered **to `main`** instead of `imap`, then Postfix is routing the internal address through the relay transport. This points to a misplaced entry in the transport table or the relay domain list. Fix the configuration; do not conclude H1 is false.
- If the copy is **not made at all** for relayed mail but is made for a test recipient that is delivered locally, then H1 is false. Prove this with a second test (a local virtual recipient with a BCC rule). The contrast is the evidence.
- Do not touch the catch-all in this ticket.
