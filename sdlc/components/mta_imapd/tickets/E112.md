# E1-12: Findings report and go/no-go

**Epic:** E1 (mta + imap prototype)
**Size:** S
**Depends on:** all other tickets in the epic
**Hypotheses covered:** all (final summary)

## Context

This is the closing ticket. Its job is to turn the work of eleven tickets into one clear document that answers three questions: what did we learn, what changes in the design, and may the next epic begin. It also brings `technical.md` back in line with reality, so nobody builds on an outdated assumption.

## What to do

1. Complete `docs/FINDINGS.md` with this structure:
   1. **Summary:** five or fewer sentences. Did the central trick (relay plus copy plus two-name mailbox) work?
   2. **Versions:** the exact Debian release, Postfix version and Dovecot version used, and the sink image.
   3. **Identity plan:** user and group IDs.
   4. **Hypothesis results:** a table of H1 to H10 with columns: result (PASS, FAIL, or CHANGED), one-sentence explanation, link to evidence in `docs/evidence/`.
   5. **Design changes:** every place where the prototype taught us something that differs from `technical.md` or the PRD, and what changed. Include any fallback that was applied, why, and its effect on later epics.
   6. **Reload table:** copied or linked from E1-09.
   7. **Retry timing recommendation:** from E1-07.
   8. **Rate limit parameters:** from E1-08.
   9. **Unexpected findings:** anything surprising that is not covered above, including problems that worked in the end but took effort.
   10. **Open questions for later epics.**
2. Update `technical.md`:
   - Replace every **(verify)** marker that this epic resolved with the confirmed fact, and remove the marker.
   - Update the sections that changed (table types, ports, rate-limit text, retry settings, sender-login handling, internal domain name).
   - Add a short "Prototype results" reference pointing to `docs/FINDINGS.md`.
3. Update the PRD **only** if a finding contradicts a requirement or a risk (for example, if "accept any address" behaves differently from what FR-3 states). Otherwise leave it unchanged. List any PRD change in `FINDINGS.md` section 5.
4. Record the **go/no-go decision** for Epic 2 (`dkim`) at the end of the document:
   - **GO:** all hypotheses passed or changed in a way that is already handled.
   - **GO WITH CHANGES:** a fallback was applied and re-tested; the changes are listed.
   - **NO-GO:** a fundamental assumption failed with no acceptable fallback; the options are listed with a recommendation.
5. Do a final **clean-checkout run**: clone the repository fresh, follow only the README, and run `prototype/tests/run-all.sh`. Record the result and the time it took.
6. Tag the repository (for example `e1-complete`) so later epics can reference this exact state.

## Acceptance criteria

- `docs/FINDINGS.md` contains all ten parts, and every hypothesis has a result and linked evidence.
- No **(verify)** marker remains in `technical.md` for anything this epic covered.
- The go/no-go decision is written, and if it is not GO, the reasons and the options are explicit.
- The clean-checkout run passes.
- The repository carries the `e1-complete` tag.
- The latest push to `main` has a green pipeline, and the published `mta` and `imap` images carry the commit hash of the `e1-complete` tag (ticket E1-13).
- Someone who did not do the work can read `FINDINGS.md` alone and understand what is known, what is decided, and what to do next.

## How to test

```
git clone <repo> /tmp/e1-check && cd /tmp/e1-check
docker compose up -d --build
prototype/tests/run-all.sh
grep -n "verify" technical.md          # list remaining markers; each must belong to a later epic
```

## Notes and pitfalls

- Resist the urge to call a half-passed hypothesis a pass. The report is useful only if it is honest. If something worked "mostly", say what did not.
- A finding that changes the design must be visible in the first section of the report, not buried in the details.
- Keep the report factual. Opinions about what to build next belong in the go/no-go section only.

## Outputs

Completed `docs/FINDINGS.md`, updated `technical.md`, go/no-go decision, repository tag.
